# Videooo V1 Specification

Status: accepted product direction / implementation baseline

## 1. Product statement

Videooo turns a topic into a researched, collaboratively written, human-narrated educational video.

The user should mainly do three things:

1. choose what to explain;
2. collaborate with the agent until the script is worth saying;
3. record the approved script.

Everything after recording should be automatable: alignment, visual planning, scene generation, composition, visual QA, and export.

> Give Videooo a topic. Discuss the script until it is right. Say it. Videooo directs the visuals.

## 2. Design principles

### Human-owned explanation

The user is the speaker and final editorial authority. Videooo may research and propose language, but it must never silently change an approved script.

### Script-first, human-narrated, audio-synchronized

The script establishes meaning. Human narration establishes timing. Visuals follow the final recording rather than forcing the narration into pre-rendered timing.

### Research before rhetoric

Factual claims are assembled into a Research Pack before a serious script draft. Important claims preserve provenance so script revisions and later descriptions can trace them.

### Scene IR before renderer code

The storyboard compiles into renderer-neutral Scene IR. Manim and Remotion are implementation targets, not the planning model.

### Deterministic core, agent-driven edges

Workflow state, artifact contracts, validation, and persistence are deterministic code. Research, writing, visual ideation, and semantic QA are expressed as Agent Skills.

### Renderer specialization

Remotion owns the final timeline. Manim is used when mathematical or scientific relationships benefit from specialized animation.

## 3. V1 scope

V1 targets 3–10 minute, 16:9 educational explainers with one human narrator.

Supported visual families:

- title and chapter cards;
- typography and key-point emphasis;
- code and structured text;
- concept cards and comparisons;
- diagrams and lightweight flows;
- equations, vectors, plots, algorithms, and scientific concept animations;
- referenced images and local media;
- captions;
- recap and summary scenes.

V1 does not require AI avatars, cinematic text-to-video, automatic screen operation, 3D production, multi-speaker dialogue, a full NLE UI, voice cloning, or TTS.

## 5. Research phase

Input:

- topic;
- optional audience;
- optional desired duration;
- optional questions or angle;
- optional source constraints.

Output: a Research Pack containing core questions, claims, source records, confidence labels, examples, misconceptions, definitions, analogies, visual opportunities, and unresolved points.

Every substantive factual claim should reference one or more source IDs. Research may be incomplete; uncertainty must be represented rather than hidden.

## 6. Script phase

The first draft is spoken-language copy, not an essay. It optimizes for comprehension, cadence, and visual teachability.

A useful default structure is:

```text
Hook -> Problem -> Intuition -> Mechanism -> Example -> Detail -> Recap
```

Each section contains purpose, narration, supporting claim IDs, optional visual hints, and revision notes.

The user may give natural-language editorial feedback such as “too academic,” “explain intuition first,” “cut the first 30 seconds,” or “move the formula later.” Each accepted revision creates a new script version.

Approval is explicit. An approved version is immutable. Any later text change creates a new draft and returns the project to script review.

## 7. Human narration

The user records the approved script with any suitable recording application.

V1 accepts an audio file and does not synthesize the narrator voice.

The recording may differ slightly from the approved text. Alignment stores both expected and recognized spoken text and reports meaningful divergence.

## 8. Transcript and alignment

Input: approved script + narration audio.

Output:

- utterance segments;
- word timestamps where available;
- pauses;
- script deviations;
- total duration.

Persisted time uses integer milliseconds. Aligned narration becomes the authoritative timing source for all subsequent scenes.

## 9. Storyboard planning

The Storyboard Agent groups narration into semantic teaching beats rather than fixed time windows.

For each beat it answers:

1. What should the viewer understand now?
2. What should be visible?
3. What should change while the sentence is spoken?
4. Is animation actually useful?
5. Which renderer fits best?

A storyboard scene includes narration range, teaching goal, visual strategy, density budget, candidate renderer, transition intent, and asset requirements.

## 10. Scene IR

Scene IR is the central contract between planning and rendering.

```json
{
  "id": "scene_attention_order",
  "startMs": 12400,
  "durationMs": 7400,
  "narrationSegmentIds": ["seg_04"],
  "teachingGoal": "Show that attention alone does not encode token order.",
  "renderer": "manim",
  "visualKind": "concept-animation",
  "objects": [
    { "id": "tokens", "kind": "token-row" },
    { "id": "edges", "kind": "attention-edges" }
  ],
  "actions": [
    { "atMs": 500, "type": "appear", "target": "tokens" },
    { "atMs": 2100, "type": "swap", "target": "tokens" },
    { "atMs": 4300, "type": "emphasize", "target": "edges" }
  ]
}
```

Required fields: stable scene ID, timing, narration references, teaching goal, visual kind, preferred renderer, ordered actions, optional assets, optional on-screen text, and optional QA constraints.

Scene IR describes intention and timing, not low-level React or Python source.

## 11. Visual routing

Remotion is the default for titles, chapters, typography, captions, code, lists, image layouts, comparisons, summary cards, and media composition.

Manim is the default for equations, coordinate systems, vectors, graphs, geometry, algorithm state transitions, scientific visualizations, and concept animation whose meaning depends on spatial transformation.

Routing is overridable when the other renderer produces a clearer result.

## 12. Remotion role

Remotion is the final compositor and global timeline owner.

Responsibilities:

- final frame rate and resolution;
- global sequencing;
- narration audio;
- captions;
- transitions;
- reusable educational components;
- embedded media;
- placement of Manim output;
- final export.

Videooo should use Remotion's official Agent Skills rather than copy them into the repository.

## 13. Manim role

Manim is an out-of-process specialized renderer.

A future Manim worker receives Scene IR plus style tokens and produces deterministic scene media and render metadata. It should support reproducible command lines, render logs, still-frame debug output, and compositable output where appropriate.

Manim output is an input to Remotion, never the complete final video.

## 14. Visual system

V1 uses one coherent design system rather than per-scene generated styling.

Design tokens should cover canvas/background, typography scale, spacing, semantic colors, highlight behavior, code style, equation style, caption safe area, radius, elevation, motion duration, easing, and transition language.

Agents choose from the system instead of inventing arbitrary presentation styles.

## 15. QA loop

A successful render is not acceptance.

V1 QA has four layers:

- Structural: timing bounds, missing assets, failed renders, invalid ranges.
- Visual: overflow, clipping, occlusion, contrast, caption collisions, empty frames, excessive density.
- Semantic: whether sampled frames genuinely support the narration and teaching goal.
- Continuity: abrupt style, scale, alignment, or transition changes across scene boundaries.

QA findings are associated with scene IDs. Repair targets only failing scenes, then re-composes the final timeline.

## 16. First-party Agent Skills

V1 defines four orchestration skills:

- `research`: topic -> sourced Research Pack;
- `script`: spoken draft + revision loop + explicit approval boundary;
- `storyboard`: aligned narration -> semantic beats -> Scene IR;
- `video-qa`: render evidence -> scene-scoped findings.

Renderer-specific knowledge can come from external official skills, especially Remotion's.

Proposed project folder:


Caches, temporary files, and heavy renders are ignored by Git by default.

## 18. Canonical states

- `topic`
- `research`
- `draft-script`
- `script-review`
- `approved`
- `recorded`
- `aligned`
- `storyboarded`
- `rendering`
- `qa`
- `done`

The workflow package owns allowed transitions. Model output cannot bypass the state machine.

## 19. CLI direction

Planned commands:

```text
videooo init <topic>
videooo status
videooo research
videooo script draft
videooo script revise
videooo script approve
videooo narration add <file>
videooo align
videooo storyboard
videooo render [--scene <id>]
videooo qa
videooo export
```

The foundation implements only `init`; later PRs fill the remaining commands.

## 20. Provider boundaries

V1 must not hard-wire one model or agent provider.

Provider interfaces will cover research/search, language-model completion, transcription/alignment, and vision review. Codex, Claude Code, or future harnesses should be able to drive the same repository skills without changing project artifacts.

This follows Orven's useful architectural lesson: keep the neutral core independent from harness-specific adapters.

## 22. CI

Every pull request and push to `master` runs:

1. Agent Skill metadata validation;
2. TypeScript project-reference build/typecheck;
3. Oxc lint;
4. unit tests.

Baseline CI requires no secrets or paid APIs. Renderer integration tests that require browsers, media runtimes, or model credentials belong in later optional jobs.

## 23. Open-source safety

Never commit API keys, private narration recordings, private research data, local absolute paths, generated caches, or proprietary fonts without redistribution rights.

Example configuration contains environment-variable names only.

## 24. Milestones

### M0 — foundation

Repository, domain contracts, workflow state machine, CLI init, first-party skill shells, CI.

### M1 — research and collaborative script

Research provider, Research Pack persistence, script drafting, revision loop, explicit approval, provenance checks.

### M2 — narration and alignment

Narration import, transcription/alignment provider, script-difference reporting, timing persistence.

### M3 — storyboard and Remotion

Semantic scene segmentation, Scene IR compiler, design tokens, Remotion component library, first end-to-end rendered explainer.

### M4 — Manim

Manim worker, renderer routing, deterministic scene renders, Remotion composition of Manim clips.

### M5 — QA and regeneration

Frame sampling, structural checks, visual/semantic review, scene-scoped regeneration, final export report.

## 25. V1 acceptance criteria

V1 is successful when a user can provide a topic, receive sourced research and a draft, iteratively revise and explicitly approve the script, record it, import the narration, automatically obtain alignment and a storyboard, render appropriate scenes with Remotion/Manim, automatically identify obvious failures, repair affected scenes, and export a coherent 1080p teaching video without manually editing the timeline.

The quality bar is not “render completed.” The result must work as a teaching artifact.
