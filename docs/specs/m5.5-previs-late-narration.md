# M5.5 — Previs and Late Narration

Status: implementation target

## Goal

Allow Videooo to produce a useful silent preview before narration exists, while preserving the existing human-narrated final workflow.

```text
approved script
  -> estimated timing
  -> semantic storyboard
  -> preview Scene IR
  -> silent preview.mp4

later:

human narration
  -> real alignment
  -> retime the existing semantic storyboard
  -> final Scene IR
  -> normal render / QA
```

## Principles

1. Previs is a side path. It must not fake the project into the `aligned` state.
2. The main project remains `approved` while preview work is produced.
3. Approved script remains immutable.
4. Preview timing is explicitly estimated, never presented as real alignment.
5. Preview visual planning is reusable after narration arrives.
6. Real narration remains the final timing authority.
7. No per-project React/Manim source is introduced.

## Project layout

```text
.videooo/
  previs/
    timing.json
    storyboard.json
    scenes/
      scene_001.json
      ...
    manim/
      generated/
      media/
    renders/
      scenes/
      preview.mp4
      render.json
```

Production artifacts remain outside `previs/`.

## Estimated timing

Add:

```ts
interface EstimatedTiming {
  schemaVersion: 1
  id: string
  projectId: string
  scriptVersionId: string
  createdAt: string
  method: 'heuristic'
  durationMs: number
  targetDurationMs?: number
  sections: EstimatedSectionTiming[]
}

interface EstimatedSectionTiming {
  sectionId: string
  startMs: number
  endMs: number
  durationMs: number
}
```

### Heuristic

For each approved script section:

- Latin-like word: about 360 ms;
- CJK character: about 220 ms;
- comma-like pause: +120 ms;
- sentence-ending punctuation: +260 ms;
- newline/paragraph pause: +350 ms;
- minimum section duration: 1500 ms.

If `ProjectBrief.targetDurationSeconds` exists, scale all section durations proportionally to hit that target exactly.

Persist integer milliseconds and contiguous section ranges.

## Previs storyboard

Add a preview-specific artifact:

```ts
interface PrevisStoryboardArtifact {
  schemaVersion: 1
  id: string
  projectId: string
  timingId: string
  createdAt: string
  video: VideoFormat
  scenes: StoryboardScene[]
}
```

It uses the same scene vocabulary and visual router as production storyboard.

Validation rules are the same as normal storyboard except the timeline source is `EstimatedTiming`, not `NarrationAlignment`.

## Preview compilation

`videooo previs storyboard compile` writes preview Scene IR under:

```text
.videooo/previs/scenes/
```

Preview Scene IR uses the same renderer contracts as production.

## Preview rendering

`videooo previs render`:

1. loads preview Scene IR;
2. renders/caches Manim preview scenes when required;
3. composes all scenes in the shared Remotion runtime;
4. renders without narration audio;
5. writes:
   `.videooo/previs/renders/preview.mp4`.

The shared Remotion runtime therefore makes narration optional.

Existing production render behavior remains unchanged because production CLI still always supplies the preserved human narration.

## Late narration

Because the main project stays `approved`, later narration works unchanged:

```bash
videooo narration add narration.m4a
videooo align --provider whisper-cpp ...
```

After real alignment reaches `aligned`, run:

```bash
videooo previs promote
```

This converts the preview storyboard into a normal production storyboard using real timing.

## Retime algorithm

The preview storyboard retains semantic section references and provisional absolute times.

Promotion creates a piecewise-linear mapping from estimated section-start anchors to real aligned section-start anchors:

```text
estimated section 1 start -> aligned section 1 start
estimated section 2 start -> aligned section 2 start
...
estimated total duration -> aligned duration
```

Every preview scene boundary is remapped through this timing function.

This preserves:

- scene order;
- teaching goal;
- visual kind;
- content;
- transition;
- intra-section visual split proportions.

The first final scene starts at 0.
The last final scene ends at real alignment duration.
Adjacent scenes share the same mapped boundary, so the final timeline remains contiguous.

If the real alignment is missing required section timing, promotion fails instead of guessing.

## CLI

Add:

```text
videooo previs create
videooo previs timing

videooo previs storyboard import <storyboard.json>
videooo previs storyboard show
videooo previs storyboard compile

videooo previs scenes list
videooo previs route show

videooo previs render
videooo previs render --output <file>

videooo previs promote
```

### create

Requires:

- project stage `approved`;
- approved script exists.

Creates `previs/timing.json`.

### render

Does not change the main project workflow stage.

### promote

Requires:

- project stage `aligned`;
- real NarrationAlignment;
- preview timing;
- preview storyboard;
- no existing production storyboard.

Writes normal `.videooo/storyboard.json`.
Project remains `aligned`, ready for normal:

```bash
videooo storyboard compile
videooo render
```

## Codex behavior

At `approved`:

- if the user is ready to record, continue with narration;
- if the user wants to see the video first or has no recording yet, use Previs.

Previs flow:

1. `videooo previs create`;
2. build/import a semantic preview storyboard;
3. compile;
4. render preview;
5. report `.videooo/previs/renders/preview.mp4`.

When narration later arrives:

1. normal narration import/alignment;
2. `videooo previs promote`;
3. production storyboard compile;
4. normal render + QA.

Do not regenerate the storyboard from scratch unless the user wants a creative redesign.

## Non-goals

M5.5 does not add:

- synthetic speech;
- scratch TTS;
- voice cloning;
- preview QA;
- automatic narration recording;
- timeline editing UI.

Those can be added later.

## CI

Add deterministic tests for:

- English timing estimation;
- CJK timing estimation;
- target-duration scaling;
- contiguous estimated sections;
- preview storyboard validation/compile;
- piecewise retiming;
- final boundary preservation;
- missing alignment section failure;
- optional-audio Remotion composition.

Add a real Previs render smoke:

1. create a short preview Scene IR;
2. render with no narration;
3. verify non-empty H.264 MP4.

## Acceptance criteria

With no recording:

```bash
videooo previs create
videooo previs storyboard import storyboard.json
videooo previs storyboard compile
videooo previs render
```

produces:

```text
.videooo/previs/renders/preview.mp4
```

while project stage remains `approved`.

Later:

```bash
videooo narration add narration.m4a
videooo align --provider whisper-cpp ...
videooo previs promote
videooo storyboard compile
videooo render
```

reuses the same visual plan with real narration timing.
