# M5 — Visual QA and Scene-Scoped Repair

Status: implementation target

## 1. Goal

M5 closes the production loop after the first draft render.

```text
draft.mp4
  -> deterministic QA evidence
  -> Codex visual / semantic review
  -> validated QA report
  -> scene-scoped repair overlay
  -> rerender affected scenes
  -> final recomposition
  -> repeat until clean
  -> done
```

The user should not manually inspect every frame or edit a timeline.

## 2. Design principle

M5 separates deterministic evidence generation from model judgment.

### Videooo runtime owns

- structural QA;
- frame sampling;
- render-duration checks;
- scene/evidence identity;
- QA report validation;
- repair overlay validation;
- applying overlays non-destructively;
- workflow transitions.

### Codex owns

- visual review;
- semantic review;
- continuity review;
- deciding whether a visual actually helps explain the narration;
- proposing scene-scoped repairs.

Videooo does not bind M5 to a separate vision-model API.

## 3. Non-destructive repair

M5 must not overwrite:

- approved script;
- narration;
- alignment;
- original storyboard;
- original compiled Scene IR.

Repairs are stored as overlays.

```text
base Scene IR
   +
active QA repair overlay
   =
effective Scene IR
```

This preserves provenance and allows repair history to be audited.

## 4. QA lifecycle

Existing workflow already supports:

```text
rendering -> qa
qa -> rendering
qa -> done
```

M5 uses that loop directly.

### Clean path

```text
qa
  -> prepare evidence
  -> import review
  -> no blocking findings
  -> accept
  -> done
```

### Repair path

```text
qa
  -> prepare evidence
  -> import review
  -> blocking findings
  -> import repair overlay
  -> rendering
  -> render
  -> qa
  -> prepare new evidence
```

## 5. QA runs

Each QA iteration is immutable.

Canonical layout:

```text
.videooo/
  qa/
    run-001/
      evidence.json
      frames/
        scene-001__0100.png
        scene-001__0500.png
        scene-001__0900.png
        ...
      review.json
      report.json
    run-002/
      ...
    repairs/
      repair-001.json
      repair-002.json
```

The latest QA run ID is stored in the project manifest.

## 7. Sampling strategy

Default per-scene samples:

```text
10%
50%
90%
```

of scene duration.

Rules:

- clamp samples inside the scene;
- deduplicate samples that map to the same video frame;
- very short scenes may have fewer than three samples;
- sample timestamps derive from Scene IR, not arbitrary wall-clock estimates.

These samples support both in-scene layout review and adjacent-scene continuity comparison.

## 8. Frame extraction

Use local ffmpeg.

Resolution precedence:

1. `--ffmpeg <path>`;
2. `VIDEOOO_FFMPEG_BIN`;
3. `ffmpeg` on PATH.

Frame extraction output is PNG.

M5 may downscale evidence frames to 1280px maximum width for efficient agent inspection while preserving aspect ratio.

Conceptual invocation:

```bash
ffmpeg -i draft.mp4 \
  -ss <seconds> \
  -frames:v 1 \
  -vf scale='min(1280,iw)':-2 \
  frame.png
```

Failure to extract a required frame is a structural QA error.

## 9. Deterministic structural QA

`qa prepare` runs structural checks before visual review.

At minimum:

- render manifest exists;
- draft video exists and is non-empty;
- render project/storyboard/alignment IDs match current project;
- final video duration is within tolerance of alignment duration;
- Scene IR count matches project metadata;
- Scene IR timeline is contiguous;
- every Manim-routed scene has a persisted render asset;
- Manim asset file exists and is non-empty;
- frame extraction succeeds;
- every QA scene maps to existing Scene IR;
- no effective scene has unsupported content.

Structural findings are generated by the runtime and cannot be silently removed by the agent.

## 10. Duration verification

Use ffprobe.

Resolution precedence:

1. `--ffprobe <path>`;
2. `VIDEOOO_FFPROBE_BIN`;
3. `ffprobe` on PATH.

Default final-video duration tolerance:

```text
max(150 ms, one output frame)
```

A duration mismatch beyond tolerance is a blocking structural error.

## 11. Narration evidence

The QA evidence pack includes spoken text relevant to each scene.

M5 derives narration text from the approved script sections referenced by the effective Scene IR.

It does not transcribe the rendered video again.

The goal is to let Codex review:

```text
what the user is saying
+
what the visual is trying to teach
+
what the sampled frames actually show
```

## 12. QA findings

Extend the existing finding contract:

```ts
interface QaFinding {
  id: string
  sceneId: string
  severity: 'info' | 'warning' | 'error'
  category: 'structural' | 'visual' | 'semantic' | 'continuity'
  message: string
  evidenceFrameIds?: string[]
  repairHint?: string
}
```

Meaning:

- `info`: non-actionable observation;
- `warning`: improvement opportunity, non-blocking;
- `error`: blocking defect.

## 13. Agent review artifact

Codex writes only agent-generated findings:

```ts
interface QaReviewArtifact {
  schemaVersion: 1
  id: string
  projectId: string
  evidenceId: string
  createdAt: string
  findings: QaFinding[]
}
```

Allowed agent categories:

- visual;
- semantic;
- continuity.

The runtime owns structural findings.

## 14. Final QA report

When importing an agent review, Videooo creates:

```ts
interface QaReport {
  schemaVersion: 1
  id: string
  projectId: string
  evidenceId: string
  renderId: string
  createdAt: string
  findings: QaFinding[]
  blockingFindingIds: string[]
  status: 'pass' | 'fail'
}
```

Final findings are:

```text
runtime structural findings
+
validated agent findings
```

The agent cannot suppress runtime findings.

## 15. Visual review checklist

The `video-qa` skill should inspect each scene for:

### Visual

- text overflow;
- clipping;
- illegible size;
- low contrast;
- awkward empty space;
- dense visual overload;
- labels colliding with shapes;
- Manim crop/scale issues;
- unintended blank frames.

### Semantic

- visual contradicts narration;
- visual is merely decorative;
- wrong concept emphasized;
- diagram relationships are misleading;
- equation/plot state does not explain the spoken point;
- summary introduces unsupported claims.

### Continuity

- abrupt unexplained scale shifts;
- inconsistent alignment/hierarchy;
- jarring background or typography change;
- transition hides important content;
- previous/next scenes visually conflict.

## 16. QA acceptance

CLI:

```bash
videooo qa accept
```

Requires:

- project stage `qa`;
- latest report status `pass`;
- zero blocking findings.

Effect:

```text
qa -> done
```

Warnings may remain.

Optional future policy can make selected warning categories blocking; not M5.

## 17. Repair overlay

Blocking findings can produce one repair artifact.

```ts
interface QaRepairOverlay {
  schemaVersion: 1
  id: string
  projectId: string
  qaReportId: string
  createdAt: string
  sceneRepairs: QaSceneRepair[]
}
```

### Scene repair

```ts
interface QaSceneRepair {
  sceneId: string
  findingIds: string[]
  visualKind?: M4VisualKind
  content?: SceneContent
  transition?: SceneTransition
  direction?: string
}
```

Restrictions:

- scene ID cannot change;
- start/end timing cannot change;
- section IDs cannot change;
- teaching goal cannot change;
- repair may change visual kind/content/transition/direction;
- changed content must validate against the resulting visual kind;
- renderer is recomputed by the deterministic visual router.

This keeps M5 repair scene-scoped.

## 18. Effective Scene IR

New package:

```text
packages/qa/
```

Responsibilities:

- structural QA;
- evidence planning;
- report validation/merge;
- repair validation;
- apply active repair overlays to base Scene IR;
- expose effective scenes.

Render uses:

```text
base scenes
 + repair overlays in creation order
 = effective scenes
```

A later repair wins only for fields it explicitly replaces.

## 20. Repair workflow

CLI:

```bash
videooo qa repair import <repair.json>
```

Preconditions:

- current stage is `qa`;
- latest report is `fail`;
- every repair scene has at least one blocking finding;
- every finding ID exists in latest report;
- every repaired scene exists;
- content validates.

Effect:

- persist repair overlay;
- append repair ID to project;
- transition `qa -> rendering`.

Then normal:

```bash
videooo render
```

uses effective scenes.

## 21. Manim repair behavior

If an overlay changes a Manim scene:

- effective Scene IR changes;
- Manim cache key changes;
- only that Manim scene rerenders.

Unchanged Manim scene assets remain reusable.

If repair changes a scene from Manim -> Remotion:

- old Manim asset stays in cache/history;
- it is not referenced by the effective render.

If repair changes Remotion -> Manim:

- the required Manim asset is generated before final composition.

## 22. Remotion repair behavior

Remotion scenes are rendered as part of final composition, so changing a Remotion scene requires only final recomposition.

M5 does not introduce per-Remotion-scene pre-render caching.

## 23. CLI

Add:

```text
videooo qa prepare
videooo qa prepare --ffmpeg <path> --ffprobe <path>

videooo qa evidence
videooo qa import <review.json>
videooo qa report

videooo qa repair import <repair.json>

videooo qa accept
```

### prepare

- requires stage `qa`;
- computes effective scenes;
- runs structural QA;
- extracts evidence frames;
- writes immutable evidence run;
- updates `qaRunId`.

### import

- validates agent review;
- merges structural findings;
- writes final report;
- updates `qaReportId`.

### repair import

- validates scene-scoped overlay;
- transitions back to rendering.

### accept

- requires pass report;
- transitions to done.

## 24. Automated Codex loop

Update `video-qa` skill.

At stage `qa`:

1. run `videooo qa prepare`;
2. read evidence metadata;
3. inspect evidence frames;
4. write a review artifact;
5. run `videooo qa import <review.json>`;
6. inspect `videooo qa report`;
7. if pass, run `videooo qa accept`;
8. if fail, create scene repair overlay;
9. run `videooo qa repair import <repair.json>`;
10. run `videooo render`;
11. repeat.

Default maximum automatic repair iterations:

```text
3
```

After three unsuccessful rounds, stop and report remaining blocking findings to the user instead of looping indefinitely.

## 25. Repair guidance

The QA skill should prefer the smallest effective change.

Examples:

- text too dense -> shorten on-screen text, keep narration unchanged;
- diagram labels collide -> change positions/content layout;
- equation too complex -> split displayed equation content within same scene contract where possible;
- wrong visual kind -> switch visual kind while preserving teaching goal;
- summary introduces extra claim -> remove unsupported bullet;
- transition distracts -> change to cut/fade.

Do not rewrite the approved narration to fix a visual problem.

## 26. Structural QA without vision

M5 deterministic checks are intentionally conservative.

The runtime does **not** attempt OCR, object detection, aesthetic scoring, or semantic image understanding.

Those belong to Codex visual review.

This avoids brittle local CV heuristics pretending to be pedagogical judgment.

## 27. Final output

When QA is accepted:

```text
stage = done
```

The final accepted render remains:

```text
.videooo/renders/draft.mp4
```

M5 may additionally copy/alias it to:

```text
.videooo/renders/final.mp4
```

on acceptance.

The render manifest records the accepted QA report ID.

## 30. Acceptance criteria

M5 is complete when a rendered project can automatically run:

```text
videooo qa prepare
Codex reviews frames
videooo qa import review.json

if failed:
  videooo qa repair import repair.json
  videooo render
  repeat

if passed:
  videooo qa accept
```

and satisfies:

- runtime structural findings cannot be suppressed;
- visual/semantic/continuity findings are scene-scoped;
- original storyboard and base Scene IR remain unchanged;
- repairs are auditable overlays;
- only changed Manim scenes invalidate cache;
- final narration remains unchanged;
- automatic loop stops after at most three repair rounds;
- accepted project reaches `done`;
- all CI checks green.
