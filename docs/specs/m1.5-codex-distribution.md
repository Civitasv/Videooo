# M1.5 — Codex Distribution and Multi-Project Workflow

Status: implementation target

## 1. Goal

M1.5 turns Videooo from a repository that happens to contain Agent Skills into a Codex-installable production workflow that can be used from any video project directory.

The desired user model is:

```text
Install Videooo once
        |
        v
~/Videos/project-a/   -> Codex -> .videooo/
~/Videos/project-b/   -> Codex -> .videooo/
~/Videos/project-c/   -> Codex -> .videooo/
```

The Videooo source repository contains product logic, plugin metadata, reusable skills, and the CLI runtime. Individual videos contain only project data and media.

## 2. User experience

After one-time setup, a user should be able to create a fresh folder and start Codex there:

```bash
mkdir positional-encoding-video
cd positional-encoding-video
codex
```

Then ask:

```text
Use Videooo to make an educational video about why positional encoding matters.
The audience understands basic neural networks.
Aim for about eight minutes.
```

The Videooo orchestrator skill should:

1. inspect the current working directory;
2. initialize `.videooo/` if no project exists;
3. guide the project through the current workflow state;
4. delegate research/script/storyboard/QA work to focused skills;
5. invoke the deterministic `videooo` CLI for project mutations;
6. stop at the explicit human approval boundary when required.

No per-video `npm install`, `pnpm install`, copied skills, or copied renderer source is allowed.

## 3. Distribution model

M1.5 defines two install surfaces.

### 3.1 Codex plugin

The repository root is a portable Agent Plugin.

Required layout:

```text
plugin.json
.codex-plugin/
  plugin.json
skills/
  videooo/
    SKILL.md
  research/
    SKILL.md
  script/
    SKILL.md
  storyboard/
    SKILL.md
  video-qa/
    SKILL.md
```

The portable root `plugin.json` is canonical.

The compatibility manifest at `.codex-plugin/plugin.json` exists for Codex compatibility and local authoring. OpenAI-specific presentation metadata may live there while the portable root manifest remains provider-neutral.

The legacy repository-local `.agents/skills/` directory is removed. `skills/` is the single source of truth.

### 3.2 Deterministic CLI runtime

The Codex skills do not replace deterministic project operations.

The CLI remains responsible for:

- project initialization;
- reading/writing `.videooo/`;
- artifact validation;
- workflow transitions;
- versioning;
- approval.

For M1.5 developer distribution, the CLI is installed once from a Videooo checkout with a local global link.

Future public distribution may publish the same CLI/runtime to npm or another package channel, but M1.5 must not require every video project to install dependencies.

## 4. Plugin manifests

### 4.1 Portable manifest

Root `plugin.json` follows the Agent Plugins schema:

```json
{
  "$schema": "https://agent-plugins.org/schemas/1.0.0/plugin.schema.json",
  "name": "videooo",
  "version": "0.1.0",
  "description": "...",
  "author": {
    "name": "Civitasv"
  },
  "repository": "https://github.com/Civitasv/Videooo",
  "license": "MIT",
  "keywords": ["video", "education", "research", "remotion", "manim"]
}
```

Portable plugin hosts discover `skills/` from the root automatically.

### 4.2 Codex compatibility manifest

`.codex-plugin/plugin.json` declares:

- stable identity;
- version;
- description;
- author;
- repository;
- license;
- `skills: "./skills/"`;
- interface metadata;
- onboarding skill pointing to `./skills/videooo/SKILL.md`.

It must not declare an MCP server in M1.5.

## 5. Marketplace

The repository includes:

```text
.agents/plugins/marketplace.json
```

The marketplace exposes Videooo as a Git-backed plugin from the repository root.

This supports authoring/testing with:

```bash
codex plugin marketplace add Civitasv/Videooo --ref master
```

Installation/enabling follows the supported Plugins Directory/local marketplace flow.

The marketplace entry must not contain credentials or machine-specific absolute paths.

## 6. Orchestrator skill

A new `videooo` skill is the main user entry point.

Its activation description should cover requests such as:

- create a teaching video;
- start a Videooo project;
- continue the current Videooo project;
- research/write/prepare visuals for an educational explainer.

The orchestrator reads project state and delegates rather than duplicating specialist instructions.

### 6.1 State behavior

```text
no .videooo/
  -> initialize project from user topic/brief

topic
  -> research begin

research
  -> delegate to research skill

draft-script
  -> delegate to script skill for v001

script-review
  -> discuss with human
  -> delegate revisions to script skill
  -> never approve implicitly

approved
  -> ask for/import human narration in M2

recorded/aligned/storyboarded/rendering/qa
  -> later milestone behavior
```

For states that are not implemented yet, the orchestrator reports the current milestone boundary instead of fabricating completion.

### 6.2 CLI dependency

Before mutating a project, the orchestrator checks whether `videooo` is available on PATH.

If the CLI is missing, it must not bypass validation by manually editing project JSON. It should explain that the one-time CLI installation is required.

## 7. Skills as single source of truth

Move:

```text
.agents/skills/research
.agents/skills/script
.agents/skills/storyboard
.agents/skills/video-qa
```

to:

```text
skills/research
skills/script
skills/storyboard
skills/video-qa
```

All validation, docs, and future packaging operate on `skills/`.

No duplicated SKILL.md copies are allowed.

## 8. Global CLI developer installation

Add a cross-platform repository command:

```bash
pnpm install:cli
```

It should:

1. ensure workspace dependencies are installed;
2. build the workspace;
3. globally link `@videooo/cli` using pnpm;
4. verify `videooo --version`.

The link points back to the developer checkout, so updating and rebuilding the checkout updates the linked runtime.

If pnpm global linking is not configured, the installer must fail with an actionable message instead of modifying shell profiles automatically.

## 9. CLI metadata

The CLI adds:

```text
videooo --version
videooo --help
```

The version should come from one canonical runtime/package constant rather than duplicated command output strings.

M1.5 does not change existing project artifact schemas.

## 10. Arbitrary working directory guarantee

The CLI must treat `process.cwd()` as the video project root unless a future explicit `--project` option is added.

Example:

```text
/tmp/video-a
  videooo init "A"
  -> /tmp/video-a/.videooo/project.json

/tmp/video-b
  videooo init "B"
  -> /tmp/video-b/.videooo/project.json
```

No files may be written back into the Videooo source checkout merely because the CLI was globally linked from it.

## 11. Integration tests

Add a CLI integration test that builds/runs the actual CLI from two unrelated temporary directories.

It must verify:

- project A creates `A/.videooo/project.json`;
- project B creates `B/.videooo/project.json`;
- project IDs/topics remain independent;
- `status` reads from the current cwd;
- no `package.json`, `node_modules`, or skills are copied into either project;
- source checkout project data is untouched.

The test runs without network access or model credentials.

## 12. Plugin validation

Extend CI validation to cover:

- root `plugin.json` parses as JSON;
- portable schema URL is present;
- plugin name is `videooo`;
- compatibility manifest parses;
- compatibility manifest points to `./skills/`;
- onboarding skill exists;
- every direct child of `skills/` with a SKILL.md has valid frontmatter;
- required first-party skills exist:
  - videooo
  - research
  - script
  - storyboard
  - video-qa;
- legacy `.agents/skills/` no longer exists.

This is structural validation only; CI does not contact OpenAI.

## 13. README usage

README should distinguish:

### Developing Videooo

```bash
pnpm install
pnpm check
pnpm build
```

### One-time local Codex setup

```bash
git clone https://github.com/Civitasv/Videooo.git
cd Videooo
pnpm install

```

Then install/enable Videooo through the supported Plugins Directory/local marketplace surface.

### Making a video project

```bash
mkdir ~/Videos/attention
cd ~/Videos/attention
codex
```

Then ask Codex to use Videooo.

## 15. Non-goals

M1.5 does not:

- publish Videooo to npm;
- submit Videooo to the public Plugins Directory;
- add an MCP server;
- add narration/transcription;
- implement Remotion or Manim rendering;
- copy renderer dependencies into video projects;
- auto-edit user shell configuration.

## 16. Acceptance criteria

M1.5 is complete when:

1. the repository is structurally valid as a portable plugin;
2. Codex can discover the `videooo` orchestrator and specialist skills from `skills/`;
3. the existing CLI can be globally linked once;
4. the CLI exposes `--version` and `--help`;
5. two unrelated temporary directories can create independent Videooo projects;
6. project directories contain no Videooo development dependencies;
7. plugin/skill validation is part of `pnpm check`;
8. README documents the one-time install and multi-project workflow;
9. all CI checks pass.
